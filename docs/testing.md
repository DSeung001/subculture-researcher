# 테스트 원칙

## 검증 범위

- **단위:** 함수·규칙의 입력과 결과를 검증한다.
- **시스템:** 여러 모듈을 연결해 API 응답·저장 결과·빌드 산출물을 검증한다. 외부 HTTP와 Firestore는 대체한다.
- **E2E:** 브라우저 조작부터 실제 애플리케이션 응답·화면 결과까지 연결해 검증한다. 현재 `test_browser_ui.py`는 요청을 대체하는 브라우저 회귀 검사이며, Flask까지 연결된 E2E는 아니다.

## 남길 테스트와 지울 테스트

- 동작 변경에는 실제 버그·요구사항을 검증하는 오프라인 회귀 테스트를 추가한다. 정상 동작, 의미 있는 경계값, 실패 결과를 확인한다.
- **동작이 깨져도 통과하는 허수 테스트, 구현을 그대로 복제한 테스트, 중복 테스트는 삭제한다.** Mock이 돌려준 값을 그대로 확인하거나 mock 호출만 확인하면서 실제 결과를 검증하지 않는 테스트도 정리한다.
- **소스·템플릿에 특정 문자열, CSS 클래스, 함수명, 코드 조각이 있는지만 확인하는 불필요한 텍스트 검사는 삭제한다.** 필요한 검증은 API 결과·구조화된 산출물·DOM 상태·사용자 조작 결과로 바꾼다. 문구 자체가 요구사항이거나 계층 의존성·설정 정책을 검증하는 경우는 유지한다.
- 테스트 수를 늘리기 위한 테스트는 만들지 않는다. 삭제 여부는 어떤 결함을 잡는지로 판단한다. DB 쓰기 금지·외부 요청 금지처럼 부작용 자체가 요구사항인 검사는 유지한다.
- 실제 수집·운영 Firestore·배포는 검증에 사용하지 않는다. 합성 fixture, 고정 시간, 임시 디렉터리를 사용한다.

## 실행

저장소 루트에서 가상환경을 활성화한 뒤 전달 전에 실행한다.

```bash
python -m unittest discover -s tests -v
```

가상환경을 활성화하지 않았다면 macOS/Linux는 `.venv/bin/python`, Windows는 `.\.venv\Scripts\python.exe`를 사용한다. 브라우저 검사는 Playwright와 Chromium이 필요하다. skip은 통과로 간주하지 않고 이유와 미검증 범위를 보고한다.
